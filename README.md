# 灯杆故障单入仓核对系统（Flask + SQLite）

巡检台账与维修台账把**两根灯杆误认成同一根**时，故障单会挂到多个资产号上。
本系统用网页完成入仓核对：上传资产号清单、故障单与同杆确认，按同杆关系把灯杆并成
冲突组，给出“撤销一条同杆确认即可让组内每张单都有唯一资产号”的方案；选定后按
**最新资料复算**，条件满足才撤销并生成整组入仓清单。

系统同时提供**周报到报估算**：最近一周的故障单往往还没到齐，按各截点当时已知的
发生日统计，用最近 8 个已满 28 天的周算到报比例，估算最近一个已结束周在周末后
第 28 天的累计单量。

## 一、启动（Docker Compose）

```bash
docker compose up --build
# 浏览器打开 http://localhost:8000
```

SQLite 数据文件落在宿主机 `./data/recon.db`（compose 已挂载卷），重建容器不丢数据。
停止：`docker compose down`。

本地演示周报到报估算（可选）：

```bash
docker compose exec web python scripts/load_demo.py   # 或宿主机：python scripts/load_demo.py
# 打开 http://localhost:8000/forecast ，台账选 LEDGER_DEMO，截止日选昨天
```

## 二、CSV 格式（均为 UTF-8，首行表头）

| 上传类型 | 列 | 说明 |
|---|---|---|
| 资产号清单 | `asset_no,pole_source,pole_no` | 资产号全局唯一；后两列是该资产所在灯杆的来源台账与灯杆号。**全量替换**（已有单子核对到资产时拒绝替换） |
| 故障单 | `ticket_no,source,pole_source,pole_no[,occurred_on]` | 单号按来源台账区分；可补传，同 `(source,ticket_no)` 为更新。`occurred_on` 为可选发生日（YYYY-MM-DD），**留空沿用该单已知日期**；补填/更正随单一起入库 |
| 同杆确认 | `source_a,pole_no_a,source_b,pole_no_b[,confirmed_by]` | 被认成同一根的两根灯杆引用；可补传，幂等；撤销后同对灯杆可再次确认 |

样例见 `sample_data/`。编号在页面统一显示为 `来源/编号`，从根上区分不同台账的同号灯杆/单号。

## 三、核对与撤销规则（实现要点）

1. **按来源区分编号**：灯杆、故障单都以 `(来源, 台账内编号)` 为自然主键，不同台账同号互不覆盖。
2. **同杆确认可传递**：活动确认构成无向图，并查集求连通组；一张确认撤销后只影响它所在的组。
3. **冲突组**：含 ≥2 个灯杆引用且有故障单的连通组。组内资产号候选池为各灯杆上资产号的并集，
   每张故障单必须匹配不同资产号（二分图 Kuhn 匹配，确定性结果）。
4. **单条撤销方案**：逐条模拟“移除该确认”，当且仅当拆出的每个子组都能一一匹配时列为方案，
   页面同时给出撤销后每张单的归属资产号；没有任何确认可满足时提示**无解**。
5. **选定方案后按最新资料复算**（不依赖选方案时的快照）：
   - 重新定位组、确认该确认仍活动且仍在组内（资料已变则要求**重新选择**）；
   - 模拟撤销重新匹配；
   - **已核对单子归属不变**、且最新组里的新单也都有唯一归属，两个条件同时满足才执行；
   - 撤销确认、锁定归属、生成整组入仓清单在**单个 SQLite 事务**内完成；
   - 条件不符或写入失败一律回滚，保留原关系和归属并提示原因。
6. 已核对单在后续匹配中作为强制边：原归属资产不在组内或被迫改变时，方案直接判失败。

## 四、周报到报估算（实现要点）

1. **发生日历史**：故障单首次入库记一条 `ticket_event`，之后每次发生日补填/更正再记一条
   （UTC 时间戳）；只改灯杆不记。任一截点都按“当时已知的发生日”取数。
2. **口径**：按 UTC 自然周（周一至周日）归单；周龄 = 截止日 − 周日（天）。
   待估周 = 截止日当日已结束的最近一个周；参考周 = 此前最近 8 个已满 28 天的周
   （周日恰为待估周日前 28+7k 天，k=0..7）。
3. **到报比例**：分母 = 各参考周在周末后第 28 天归入该周的单数；分子 = 其中在与待估周
   相同周龄时已归入该周的单（分子是分母的子集）。比例 = 分子合计 ÷ 分母合计（8 周合并）。
4. **预计**：第 28 天预计单数 = 待估周已报数 ÷ 到报比例（页面保留 1 位小数）。
   分母或比例为零时不给预计数，只给已报数与原因；缺发生日的单不归入任何周，单独计数。
5. **一致性**：整次估算在单个 SQLite 读事务内完成，读取同一份已提交数据；
   截止日必须是已过去的日期（早于 UTC 今天）。

## 五、页面

- `/` 上传三种 CSV；展示数据统计、冲突组（当前是否可唯一归属、已选方案、入仓链接）、上传批次。
- `/groups/<key>` 组详情：故障单/候选资产/已核对锁定单；列出全部单条撤销方案及撤销后归属；无解提示。
- `/warehouse/<id>` 整组入仓清单：每张单的唯一资产号，标注“已核对（归属保持不变）/本次新核对”。
- `/forecast` 周报到报估算：选台账与已过去的截止日，给出最近一个已结束周的已报单数、
  缺发生日单数（另计）、8 个参考周的分子/分母明细、到报比例与第 28 天预计单数（或无法估算的原因）。

## 六、验证

自动化测试（两套共 18 个用例，Flask test client + 临时 SQLite）：

```bash
python tests/test_recon.py      # 入仓核对 9 个用例
python tests/test_forecast.py   # 周报到报估算 9 个用例
```

`test_recon.py` 覆盖：三类上传与补传/幂等、来源编号区分、传递分组、方案选择与撤销入仓、
**补传后仍可撤销（已核对单归属不变）**、**补传后无解与须重选**、坏 CSV 整体拒收、
写入失败事务回滚保留原关系。

`test_forecast.py` 覆盖：发生日新建/留空沿用/更正/非法日期拒收/老格式 CSV 兼容、
事件历史只随发生日变化记录、**迟到补报**（进分母不进分子）、**跨周更正**（更正出离开分母、
更正入第 28 天进分母）、截止日后补报不计入已报、缺发生日另计（含截止日后才补填仍属缺发生日）、
分母为零与比例为零只给已报数和原因、**整次估算单个读事务**、老库迁移补初始事件、
页面表单与截止日校验。

另做过真实 HTTP 冒烟：演示脚本造 8 个参考周 + 待估周（含迟到补报、双向跨周更正、
截止日后补报/补填），页面显示已报 9、缺发生日 2、比例 82.5%（80/97）、预计 10.9，
与手算一致；上传带发生日 CSV、更正发生日、非法日期拒收、截止日校验均符合预期。

## 八、余项与边界

- 资产清单按“全量替换”设计；若已产生核对关系，上传会被拒绝并提示，避免静默读旧归属。
- 单机部署、SQLite 单文件；如需多实例，可换 PostgreSQL（DAO 集中在 `db.py`/`services.py`）。
- 未做登录鉴权，内网工具定位；上生产前需加认证并替换 `app.secret_key`。
- 冲突组只展示由同杆确认合并出来的多灯杆组；单灯杆自身“单多于资产”的资料问题不在本流程处理范围。
- 发生日历史自本功能上线起记录；上线前的存量单在迁移时补一条初始事件
  （以迁移时刻为首次已知时间，发生日取当前值），更早的逐日状态无法回追。
- 发生日只校验是合法日期，不限制未来日期；未来发生日的单按其所在周正常归入。
- 到报比例按 8 个参考周合并计算（分子合计 ÷ 分母合计），不按周简单平均；
  预计单数保留 1 位小数展示，未做取整。
- 估算为只读统计，不回写任何表；`occurred_on` 的补填/更正只通过故障单 CSV 上传进行。
